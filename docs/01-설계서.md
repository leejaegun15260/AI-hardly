# 병역진로설계 상담도구 설계서

> 읽는 분께: 어려운 말은 최대한 빼고, 비유를 섞어 썼습니다.
> 순서대로 읽으시면 "무엇을 · 왜 · 어떤 순서로" 만드는지 이해되도록 구성했습니다.

---

## 1. 이 도구가 하는 일 (한 문장씩)

상담을 받으러 온 청년에게 이 도구는 네 가지 질문에 답해줍니다.

| # | 청년의 질문 | 도구가 하는 일 | 이름 |
|---|---|---|---|
| 1 | "제 전공/자격증으로 갈 수 있는 특기가 뭐예요?" | 조건에 맞는 특기를 찾아서 순위를 매김 | **탐색** |
| 2 | "그 특기는 무슨 일을 하나요?" | 임무·신체조건·면접여부·구비서류를 보여줌 | **이해** |
| 3 | "저 지금 몇 점이에요?" | 배점표대로 항목별 점수를 계산 | **진단** |
| 4 | "붙을 수 있어요? 뭘 더 해야 해요?" | 최근 3년 커트라인과 비교 → 부족분을 채울 방법 제시 | **처방** |

이 네 개가 곧 화면 4개이고, 만드는 순서도 이 순서입니다.
**앞의 것이 없으면 뒤의 것을 못 만듭니다.** (특기 목록이 없으면 점수도 못 냅니다.)

---

## 2. 가장 먼저 알아야 할 사실 — 데이터는 세 종류다

초보자가 가장 많이 실수하는 지점입니다.
"공공API 쓰면 다 되겠지"라고 생각하는데, **커트라인은 API가 아닙니다.**

### (가) 실시간으로 불러오는 것 — 오픈API

주소를 부르면 그 자리에서 최신 값을 돌려줍니다. (자판기 같은 것)

- 모집병 **군사특기 정보** — 특기별 임무, 신체조건, 면접 실시 여부
- 모집병 **군별·특기별 지원가능 정보** — 특기별로 인정되는 **자격/면허, 전공학과** ← 추천 기능의 심장
- 모집병 **구비서류**
- 모집병 **군지원 접수현황** — 지원자 수 (경쟁률 계산용)
- 맞춤형 특기병 정보 — 특기별 선발 인원

### (나) 파일로 받아서 쌓아두는 것 — 파일데이터(CSV)

버튼을 눌러 엑셀을 내려받는 방식이고, 1년에 한두 번만 갱신됩니다. (도서관 연감 같은 것)

- 육군 기술행정병 **1차 합격 커트라인**
- 공군병 모집직종별 **1차 선발 커트라인·선발인원**
- 해병대병 모집직종별 **1차 선발 커트라인·선발인원**

**"3년간 같은 시기 점수 비교"는 전부 이 파일에서 나옵니다.**
→ 그래서 이 도구는 *반드시* **데이터를 모아 저장해두는 창고(DB 또는 JSON 파일)** 가 필요합니다.
→ 매년 새 파일이 올라오면 사람이 받아서 넣어주는 **갱신 작업**이 운영의 핵심 일거리입니다.

### (다) 규칙(배점표) — API가 있지만 확인이 필요한 것

"자격증 기사 이상 50점, 산업기사 45점…" 같은 **점수 매기는 규칙**에 대해
아래 두 API가 존재합니다. (2026-09 확인)

- 병무청_**모병합격 배점기준** — https://www.data.go.kr/data/3066490/openapi.do
- 병무청_**모병 개별특기 배점구분** — https://www.data.go.kr/data/3066491/openapi.do

**다만 이 API가 배점표 전체를 주는지는 실제로 호출해봐야 압니다.**
그래서 다음 순서로 갑니다.

1. `scripts/probe_api.py` 로 호출해 **무엇이 오는지 먼저 확인** (→ [05번 문서](05-API-연결하기.md))
2. 배점표가 충분히 오면 → 규칙 파일을 API에서 자동 생성
3. 부족하면 → 병무청 누리집 *평가요소 및 배점기준* 페이지를 보고 사람이 채움

어느 쪽이든 결과는 `rules/2026-army-tech.json` 처럼 **연도별 파일**로 관리합니다.
기준이 개정되면 파일만 갈아끼우면 되도록 만드는 것이 요령입니다. (코드에 숫자를 박아넣지 말 것)

> **정리**: API(실시간) + 파일(창고에 쌓기) + 규칙(API 확인 후 부족분은 직접 입력)
> = 세 다리로 서는 도구입니다.

## 3. 만들 순서 — 5단계

### 0단계. 준비 (약 3일, 대부분 기다리는 시간)  — 절차는 [05번 문서](05-API-연결하기.md)

1. **공공데이터포털(data.go.kr) 회원가입** → 위 API들 **활용신청**
   - 개발계정은 즉시, **운영계정은 승인에 1~2일** 걸립니다. 먼저 신청해두고 다른 일을 하세요.
   - 인증키는 1인 1개, 양도 불가입니다.
2. **커트라인 CSV를 먼저 내려받아 엑셀로 열어봅니다.**
   - 열 이름이 뭔지, 특기명이 API의 특기명과 **글자가 똑같은지** 확인 (이게 뒤에서 제일 큰 함정입니다)
3. 병무청 **평가요소 및 배점기준** 페이지를 인쇄해서 옆에 둡니다.

> 이 0단계를 건너뛰고 코드부터 짜면 100% 다시 만들게 됩니다.
> **"데이터 실물을 눈으로 본 뒤에 설계한다"** 가 철칙입니다.

### 1단계. 데이터 창고 만들기 (1~2주) — 가장 중요

원본이 제각각이므로 **우리만의 표준 표 5개**로 정리합니다.

| 표 이름 | 한 줄이 뜻하는 것 | 주요 칸 | 출처 |
|---|---|---|---|
| `specialty` | 군사특기 1개 | 군, 모집분야, 특기코드, 특기명, 임무설명, 신체조건, 면접여부 | API (군사특기 정보) |
| `cert_index` | "이 자격증을 인정하는 특기" 목록 (자격명이 열쇠) | 자격/면허명 → 특기코드, 등급 | API (지원가능 정보) — **수집 완료** |
| `major_index` | "이 전공을 인정하는 특기" 목록 (학과명이 열쇠) | 전공(학과)명 → 특기코드 | API (지원가능 정보) — **수집 완료** |
| `cutoff` | "몇 년 몇 회차 이 특기의 커트라인" 1건 | 연도, 회차, 군, 특기코드, 커트라인점수, 선발인원, 입영부대 | CSV 파일 |
| `applicants` | "몇 년 몇 회차 이 특기 지원자 수" | 연도, 회차, 특기코드, 지원자수, 계획인원 | API (접수현황) |

**핵심 설계 포인트 — 특기코드 사전**

CSV의 특기명("일반의무")과 API의 특기명("일반의무병")이 다를 수 있습니다.
그래서 `specialty_alias`(별칭 사전) 표를 하나 더 두고, **모든 데이터를 특기코드 하나로 묶습니다.**
이 연결이 안 되면 "추천은 되는데 커트라인이 안 뜨는" 도구가 됩니다.

산출물: `scripts/collect.py`(수집) → `data/build/*.json` (앱이 읽는 표준 파일)

### 2단계. 점수 계산기 만들기 (1주)

배점표를 규칙 파일로 옮기고, 입력 → 점수를 뽑습니다. (육군 기술행정병 기준 예시)

```
자격/면허 50점  +  전공 40점  +  가산점 15점  =  총 105점
(출결 10점은 2026-09-02 확인 결과 평가 항목에서 폐지되었습니다)
```

- 자격/면허: 기사 이상 50 / 산업기사 45 / 기능사 40 / 공인 일반 30 / 비공인 26 / 미소지 20
  (운전 특기는 별도 만점 체계 — 대형·특수 90, 1종보통(수동) 87)
- 가산점: 직업선호도 검사 추천특기와 지원특기가 **일치하면 가산점**,
  국가유공자 자녀·독립유공자 손자녀 3점, 다자녀 최대 3점, 기초생활수급 3점

> 이 숫자들은 **매년 바뀔 수 있으므로** 반드시 규칙 파일에 두고, 화면에 "2026년 기준"이라고 표시하세요.

**반드시 지킬 것: "설명 가능한 점수"**
총점만 보여주면 상담이 안 됩니다. 항목마다
`자격/면허 40점 (기능사 보유) — 만점 50점, -10점` 처럼 **왜 그 점수인지 함께** 내보내야 합니다.
이 항목별 결과가 그대로 4번 화면(처방)의 재료가 됩니다.

### 3단계. 특기 추천 엔진 (1주)

입력 3가지 → 특기 후보에 점수를 매겨 정렬합니다.

| 입력 | 어떻게 쓰나 | 가중치(예시) |
|---|---|---|
| 자격/면허 | `cert_index`에서 내 자격증이 이 특기를 가리키면 적합 | 40% |
| 전공 | `major_index`에서 내 학과가 이 특기를 가리키면 적합 | 30% |
| 직업흥미유형 (Holland RIASEC 등) | 특기별 흥미유형 태그와 비교 | 20% |
| 합격 가능성 | 내 예상점수 − 작년 커트라인 | 10% |

> 흥미유형과 특기의 연결표는 공공데이터에 없습니다.
> **상담사 경험으로 만든 매핑표(엑셀 한 장)** 를 `data/build/interest_map.json`으로 두고 계속 다듬으세요.
> 이게 이 도구의 진짜 차별점입니다.

추천 결과는 세 묶음으로 보여주면 상담이 쉬워집니다:
**① 지금도 유력** / **② 조금만 더 하면 가능** / **③ 도전**

### 4단계. 시각화 화면 (2주)

| 화면 | 핵심 그림 |
|---|---|
| ① 내 정보 입력 | 3~4문항으로 끝나게. 흥미유형은 몰라도 넘어갈 수 있게 |
| ② 추천 특기 목록 | 특기 카드 = 적합도 막대 + 내 예상점수 + `작년 커트라인 대비 +6점` 배지 |
| ③ 특기 상세 | **3년 커트라인 꺾은선 그래프 + 내 점수 가로선** (가장 설득력 있는 화면), 경쟁률, 임무·신체조건·구비서류 |
| ④ 갭 분석·처방 | 항목별 막대(내 점수 vs 만점) + "이걸 하면 +N점" 목록 |

④의 예시 문구:
- `산업기사 취득 → 자격 45점 (+5점)` · 다음 시험일 안내
- `직업선호도 검사 후 특기 일치 → 가산점 대상`

### 5단계. 검증과 운영 (계속)

- **검증**: 작년 실제 합격자 3~5명의 조건을 넣어 계산 → 실제와 맞는지 확인
- **상담사 검수**: 문구가 오해를 부르지 않는지 (특히 "합격 가능"이라는 단정 표현 금지)
- **갱신 달력**: 커트라인 CSV 갱신 시기 / 배점 개정 시기를 달력에 등록
- **고지 문구**: 모든 화면 하단에 "참고용 추정치" 상시 노출

## 4. 기술 선택 — 가장 쉬운 길로

상담 창구용이므로 화려한 기술보다 **끊기지 않는 것**이 중요합니다.

**추천 구성 (초보자 친화)**

```
[ 하루 1번 ]  scripts/collect.py  ──API 호출·CSV 읽기──▶  data/build/*.json
[ 상담 중  ]  web/index.html  ──JSON 읽어서 계산·그리기──▶  화면
```

- 언어: **Python**(데이터 수집) + **순수 HTML/JS**(화면), 그래프는 Chart.js
- 저장소: 처음엔 **JSON 파일**로 충분합니다. 데이터가 커지면 SQLite로.
- 서버: 접수현황 실시간 조회가 꼭 필요할 때만 작은 서버(FastAPI) 추가

**보안 주의 1줄**: **인증키를 화면(HTML/JS)에 넣지 마세요.** 키는 수집 스크립트(서버 쪽)에서만 씁니다.

## 5. 미리 알아둘 함정 5가지

| 함정 | 대응 |
|---|---|
| 특기명이 자료마다 다름 | 별칭 사전(`specialty_alias`)으로 코드 통일 |
| 커트라인이 회차·입영부대별로 쪼개져 있음 | 비교 기준을 **"같은 회차(월)끼리"** 로 못 박고 화면에 명시 |
| 배점 기준이 해마다 개정됨 | 규칙 파일 연도별 분리 + 화면에 기준연도 표시 |
| 흥미검사 결과 API는 학번·학교코드가 필요하고 비회원 결과는 7일 후 삭제 | 상담도구는 **유형만 직접 선택**하게 하고 개인정보는 저장하지 않기 |
| "합격한다"고 오해 | 모든 수치에 "추정" 표기, 단정 표현 금지 |

## 6. MVP — 처음엔 이만큼만

욕심내면 못 끝냅니다. **육군 기술행정병 한 분야, 특기 10개**로 시작하세요.

- 대상: 육군 기술행정병
- 기능: 특기 추천 + 점수 계산 + 3년 커트라인 그래프
- 제외(2차로 미룸): 해·공군·해병대, 맞춤형특기병, 구비서류 상세, 상담 이력 저장

여기까지 되면 상담사에게 보여주고 피드백을 받은 뒤 군을 늘려가세요.
