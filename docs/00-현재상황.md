## 자격 등급 연결 (`rules/2026-army-tech.json` → `grade_alias`)

병무청 API가 주는 등급 이름과 배점표의 등급 이름이 달라서 연결표를 두었습니다.

| API 가 주는 등급 | 배점표 등급 | 점수 |
|---|---|---|
| 기사급이상 | 기사 | 50 |
| 산업기사급 | 산업기사 | 45 |
| 기능사급 | 기능사 | 40 |
| 일반면허공인 | 공인 일반자격 | 30 |
| 일반면허비공인 | 비공인 일반자격 | 26 |
| 대형/특수 | 대형·특수 | (운전 특기 별도 배점) |
| 1종보통 | 1종보통(수동) | (운전 특기 별도 배점) |
| 2종보통 | 2종보통 | (운전 특기 별도 배점) |

- **1종보통**: 자료의 자격명이 모두 `1종보통(수동)` 이어서 수동으로 봅니다.
  담당자 결정에 따라 배점표에서 `1종보통(자동)` 항목은 **삭제**했습니다.
- **등급이 빈칸인 자격 177건(모두 해군)**: 담당자 결정에 따라
  자격 이름 끝에 국가기술자격 등급(기술사·기능장·기사·산업기사·기능사)이
  분명히 붙어 있는 것만 그 등급으로 봅니다. → **103개 자격**이 이렇게 구제되었습니다.
  (`기능사보` 는 기능사가 아니므로 제외)
- **아직 정하지 않은 것** (`grade_alias_미정`, 점수에 반영되지 않음):
  - `자격등급 그외` 3건 — 육군 기독교군종 특기의 e-Test Professionals 3종. 담당자 판단으로 보류.
  - `면허등급 그외` 1건 — 공군 정보보호병의 'BoB센터 차세대 보안리더 양성프로그램 과정 선발자'.
  - 이름으로도 등급을 알 수 없는 자격 37개 — 건축사, 감정평가사, 소방시설관리사,
    전산회계운용사, 정보통신설비사, 무선인터넷관리사 등.
    전체 목록은 `data/build/_jiwon_report.json` 의 `등급을_정하지_못한_자격` 에 있습니다.

## 흥미유형 — 예술형·사회형 문제

예술형·사회형에 연결된 특기가 각 3개뿐이라 상담이 막히는 문제가 있었습니다.
담당자 확인 결과 **정책이 개선되어**, 직업흥미유형 검사의 다른 표준점수가
일정 수준을 넘으면 그 유형의 특기도 함께 추천할 수 있게 되었습니다.

화면에는 흥미유형 칸을 두 줄로 나눠 넣었습니다.

- **윗줄** — 가장 높은 유형 최대 2개. **가산점 대상**입니다.
- **아랫줄** — '표준점수가 기준을 넘은 다른 유형'. 대상자에게 해당할 때만 고릅니다.
  그 유형의 특기도 추천 목록에 나오고 «표준점수 기준» 표시가 붙습니다.
  **가산점은 붙지 않습니다.**

예) 예술형만 고르면 특기 3개 → 진취형·관습형을 아랫줄에서 고르면
육군 28개(4군 전체로는 46개)로 늘어납니다.

## 배점 구조 정정 (2026-09-02, 담당자 확인)

```
자격/면허 50  +  전공 40  +  가산점 10  =  총점 100점
```

- **출결(무단결석) 10점 폐지** — 평가 항목에서 없어졌습니다.
  입력 화면의 '무단결석' 칸과 갭 분석의 '출결 확인' 처방을 지웠습니다.
  되살릴 일이 생기면 `rules/2026-army-tech.json` 의 `폐지된_항목` 에
  폐지 전 구간이 그대로 남아 있습니다.
- **가산점 만점 15점 → 10점** — 담당자 확인.
  총점도 **115점 → 100점**이 되었습니다.
- 남은 확인거리: 가산점의 **항목별 점수**(지금은 각 3점, 예시값)는 아직
  모집공고로 확인하지 않았습니다. 네 항목을 모두 갖추면 12점이 되어
  만점 10점으로 깎입니다. 공고에서 항목별 점수를 확인하면 교체해야 합니다.
> 커트라인이 실제 자료로 바뀌면서, 배점 변경에 맞춰 샘플 커트라인을 조정하던
> `scripts/make_sample_data.py` 는 필요 없어져 지웠습니다.

병무청 제공 엑셀에서 **25년 8회차 ~ 26년 8회차, 13회차**를 옮겼습니다.

```bash
python3 scripts/import_cutoff_xlsx.py
```

| 군 | 자료 줄 | 특기와 이어 붙인 것 |
|---|---|---|
| 육군 | 121 | 118 |
| 해군 | 22 | 19 |
| 공군 | 8 | 8 |
| 해병 | 8 | 6 |
| **합계** | **159** | **151** |

**화면이 달라진 점** — 예전에는 '같은 회차끼리 3개년 비교'였는데,
이제 **회차 순서대로 13회차 흐름**을 보여줍니다.
평균 기준은 **현재 배점 적용 이후 / 최근 3회차 / 최근 6회차 / 전체**에서 고릅니다.

### 배점이 바뀐 회차를 갈라서 봅니다 (중요)

배점 기준은 회차마다 바뀌어 운용돼 왔습니다. **배점이 다르면 커트라인도 다른 잣대의 숫자**라,
여러 배점의 회차를 한꺼번에 평균내면 합격선을 잘못 잡습니다.
그래서 기본값을 **'현재 배점 적용 이후'** 로 두고, '전체 회차'를 고르면 경고를 띄웁니다.

지금은 **26년 3회차부터**로 잡아 두었습니다 (`rules` 의 `배점_적용_시작`, `confirmed: false`).

- 육군 일반 특기의 **가장 낮은 커트라인**이 26년 3회차부터 여섯 회차 내리 **정확히 40점**입니다.
  40점은 지금 배점표의 바닥(자격 미소지 20 + 전공 미해당 20)과 같습니다.
  그 앞 회차의 최저는 42~47로 제각각이라 다른 배점이었던 것으로 보입니다.
- 육군 운전 특기도 **26년 4회차부터** 바닥이 정확히 **87점**(1종보통(수동))으로 굳습니다.

같은 특기라도 기준에 따라 평균이 이만큼 달라집니다 (K-21보병전투차량승무).

| 기준 | 평균 | 회차 수 |
|---|---|---|
| 현재 배점 이후 (26년 3회차~) | **41.3** | 6 |
| 최근 3회차 | 40.3 | 3 |
| 전체 13회차 | 44.2 | 12 |

**실제 적용 회차를 담당자가 확인해 주면** `rules/2026-army-tech.json` 의
`배점_적용_시작.period_label` 을 고치고 `confirmed` 를 `true` 로 바꾸면 됩니다.

**점수를 견주지 않는 특기** — 이 배점표는 `육군 기술행정병 100점` 기준입니다.
총점 체계가 다른 특기는 커트라인 흐름만 보여주고 '몇 점 차이' 판정은 하지 않습니다.

- **해군·공군·해병** — 군마다 배점이 다릅니다. 실제로 공군 의무는 커트라인이 **106점**까지 나와
  100점 체계가 아님이 확인됩니다.
- **육군 운전 특기 6개** (수송운용·견인차량운전·차륜형장갑차운전·K-53계열차량운전·구난차량운전·크레인차량운전)
  — 최저 커트라인이 정확히 **87점**에 걸려 있습니다. 87점은 운전면허 배점표의
  '1종보통(수동)' 점수와 같아, 운전면허 별도 배점을 쓰는 것으로 보입니다.
  → `rules/2026-army-tech.json` 의 `점수비교_제외` 에 `confirmed: false` 로 적어 두었습니다.
  **모집공고로 확인이 필요합니다.**
  (지게차운전 55~66 · 차량부대정비 42~78 은 100점 체계와 맞아 제외하지 않았습니다)

**이어 붙이지 못한 8줄** (`cutoff.json` 의 `확인필요` 에 있습니다)

| 군 | 이름 | 왜 |
|---|---|---|
| 해군 | 정보통신 | 특기 목록에는 '통신'(코드 25)만 있음 — 같은 특기인지 확인 필요 |
| 해군 | 갑판 · 군사경찰 (동반입대) | 특기 목록에 없음 |
| 해병 | 동반입대 · 직계가족 | 특기가 아니라 모집 유형 |
| 육군 | 견인포병(131.101) · 155mm자주포병(131.103) | 특기 목록·지원가능정보 어디에도 없음 |
| 육군 | 도로포장장비운용(163.110.) | 특기 목록에 없음 (지원가능정보에는 503건 있음) |

> **찾아낸 자료 오류 하나** — 병무청 자료에서 `163.110`(그레이더운용)과
> `163.110.`(끝에 점, 도로포장장비운용)은 **서로 다른 특기**인데 코드가 거의 같습니다.
> 끝의 점을 지우고 맞추던 기존 코드가 두 특기를 하나로 합치고 있었습니다.
> 지금은 점을 그대로 두어 구분합니다. 지난번 자격·전공 색인도 다시 만들었습니다.

## 다음에 할 일 (순서대로)

1. **현재 배점체계 받기 (담당자 준비 중)** — 받으면 아래를 한 번에 정리합니다.
   - 기술행정병 전형 배점표 확정 (전공 구간, 가산점 항목별 점수)
   - **운전 전형**을 별도 전형으로 분리
     (담당자 확인: 운전은 **전공 점수가 없고**, 자격/면허 안에서 **운전면허 점수가 따로** 구분됨)
   - `배점_적용_시작` 회차 확정
2. **운전 특기 6개 확인** — `점수비교_제외` 의 목록이 맞는지. 배점체계를 받으면
   커트라인 비교도 켤 수 있습니다.
3. **못 이어 붙인 8줄 확인** — 특히 해군 '정보통신'이 특기 목록의 '통신'과 같은 것인지.
4. **남은 API 신청** — 군사특기 정보(3066488) → 배점기준(3066490) → 접수현황 → 구비서류.
   군사특기 정보가 오면 화면의 '모집분야·주요 임무·신체등급·면접'이 채워지고,
   접수현황이 오면 경쟁률이 붙습니다.
5. `grade_alias_미정` 에 남은 등급 처리 방침 결정.

| `web_index.json` | **화면이 읽는 색인** — 학과명·자격명으로 특기를 찾음 (4MB) | 올림 |
| `jiwon_stats.json` | 특기별 인정 전공·자격 개수 | 올림 |
| `_jiwon_report.json` | 수집 결과 요약 (등급 목록, 추정·미정 자격) | 올림 |
| `cutoff.json` | 회차별 커트라인 (**실제**) | 올림 |
| `major_index.json` (21MB) | 학과명 → 특기 목록, 사람이 읽는 형태 | 제외 |
| `cert_index.json` (15MB) | 자격명 → 특기·등급, 사람이 읽는 형태 | 제외 |
| `jiwon.sqlite` (350MB) | 받은 원본 창고 | 제외 |

> 제외한 세 개는 용량이 커서 저장소에 올리지 않습니다.
> `major_index.json` / `cert_index.json` 의 내용은 `web_index.json` 에 부피를 줄여
> 그대로 들어 있고, 화면도 그것을 읽습니다.
> 사람이 읽는 형태가 필요하면 `python3 scripts/collect_jiwon.py --rebuild` 로 다시 만듭니다.

### 왜 색인을 따로 만드나

받은 자료가 136만 건이라 브라우저에 통째로 보낼 수 없습니다. 그래서 뒤집어 놓았습니다.

```
"전기과"     → 이 학과를 인정하는 특기 번호 목록
"전기기능사"  → 이 자격을 인정하는 특기 번호와 등급
```

청년이 입력한 **이름으로만** 찾으므로 빠릅니다.
부피를 더 줄이려고 특기 번호를 36진법 두 글자로 적었습니다(4MB).
자세한 설명은 `web/index.html` 의 '이름 색인' 주석에 있습니다.
